# Mac 安装包首次连接界面设计

## 目标

把首次连接从“理解并执行终端命令”改成普通用户能完成的安装闭环：

1. 将 Mac 安装包链接发送到 Mac。
2. 打开 Mimi Remote Mac，完成首次设置。
3. 在 iPhone 或 iPad 扫描 Mac 上的二维码。

二维码配对协议、手动连接和命令行安装能力保持不变。本轮只调整入口层级，不重做连接架构。

## 方案

### 信息层级

| 层级 | 内容 | 设计理由 |
| --- | --- | --- |
| 页面标题 | `连接你的 Mac` | 保留当前用户心智和导航位置 |
| 主卡片 | 安装 → 首次设置 → 扫码 | 用真实任务顺序代替命令解释 |
| 主动作 | `扫描 Mac 上的二维码` | 已安装用户可以立即连接，也是最终完成动作 |
| 次动作 | `发送下载链接到 Mac` | iPad 不能安装 DMG，使用系统分享面板把链接交给 Mac |
| 高级入口 | 命令行安装、手动连接 | 保留专业用户和故障恢复能力，但不干扰普通路径 |
| 安全说明 | `配对信息只在你的设备之间传输。` | 在用户做出连接动作前说明隐私边界 |

### 页面文案

#### 第一步

- 标题：`安装 Mimi Remote Mac`
- 说明：`需要 macOS 15 或更高版本。将下载链接发送到你的 Mac，打开 DMG 后拖入“应用程序”。`
- 动作：`发送下载链接到 Mac`

#### 第二步

- 标题：`打开并完成首次设置`
- 说明：`选择代码目录后，Mac 会显示配对二维码。`

#### 第三步

- 标题：`扫描二维码连接`
- 主动作：`扫描 Mac 上的二维码`

#### 高级入口

- `命令行安装（高级）`
- `手动输入连接信息`

### Apple 风格约束

- 使用系统字体、Dynamic Type 和现有主题 Token，不增加自定义字体。
- 内容卡片使用稳定的实色分组表面；玻璃材质只留给系统弹层或浮动控制，不铺满内容区。
- 页面只保留一个强主动作，分享下载链接使用次级描边样式。
- 点击时立即提供系统按压反馈，不增加人为等待。
- 分享使用原生 `ShareLink`/分享面板；二维码扫描继续使用现有系统 Sheet，保持进入和退出路径一致。
- 配对成功时同时更新状态并给出一次成功触感；失败信息就地显示，不让用户提交后再猜测原因。
- 开启“减少动态效果”时取消缩放和位移动画，只保留短淡入淡出。
- 卡片在窄屏改为单列自然增高，不固定正文高度；所有交互区域至少使用系统推荐点击尺寸。

## 实现

### 最小改动范围

1. `InitialConnectionSettingsSections.swift`
   - 未配置时展示三步安装卡片。
   - 复用现有扫码入口。
   - 把 Homebrew 和 `agentd` 命令移动到“命令行安装（高级）”。
   - 保留现有手动连接 DisclosureGroup。

2. `AppExternalLinks.swift`
   - 增加稳定 Mac 安装包地址：

     ```text
     https://github.com/gaixianggeng/mimi-remote/releases/latest/download/Mimi-Remote-Mac.dmg
     ```

   - 分享固定的 `latest` 地址，避免 App 内写死发布版本。

3. `Localizable.xcstrings`
   - 增加上述中英文文案。
   - 删除主界面对 `agentd up` 的依赖；命令本身仍作为技术字符串保留在高级区域。

4. 文档
   - README、安装文档和支持文档把 DMG 调整为 macOS 普通用户主路径。
   - Homebrew 保留为高级安装、服务器和恢复路径。

### 状态处理

- `appStore.isConfigured == false`：显示三步首次设置。
- 已有连接档案：继续显示现有 Mac 管理和新增连接界面，不重复展示完整安装教学。
- Mac 已安装但移动端未配置：用户可直接跳到第三步扫码。
- 分享面板取消：不改变页面状态，也不弹错误。
- 扫码成功：验证真实连接后再进入工作台，沿用现有安全提交逻辑。

## 风险与优化

- 当前 Mac App 的最低版本是 macOS 15（#242 把部署目标从 26 降到 15），必须在发送下载链接前明确显示。降低部署目标时必须同步修改本地化文案 `ui.mac_installer_requirements_and_instructions`、`SKILL.md` 与本文件；#242 当时漏改，残留了「需要 macOS 26」的文案直到 #554 才补上。
- 在 iPad 上直接打开 DMG 下载会造成误解，因此主入口应是“发送下载链接到 Mac”，不是“立即下载”。
- GitHub 在部分网络环境下可能访问不稳定。MVP 先复用现有公开 Release；只有真实用户数据证明需要时，再增加自有稳定下载落地页，不提前引入下载代理。
- ImageGen 概念稿用于确认层级和视觉方向，不作为像素级实现源。最终界面应使用 SwiftUI 原生组件和现有主题系统实现。
