# Mimi Remote 中国大陆提交清单

## 目标

在不隐藏真实功能、不冒充第三方官方产品的前提下，把 Mimi Remote 作为“连接用户自有计算机的自托管开发工作台与可选托管连接”提交到中国大陆 App Store。

KittyLitter 已在中国大陆商店提供，说明“移动端连接用户自有开发运行时”这一产品形态存在审核先例；但不同账号主体、二进制、元数据和审核批次不能互相替代，本清单仍以 Mimi Remote 的历史拒绝信息和当前实现为准。

- [x] 公开推广文本、描述和关键词不使用 ChatGPT/OpenAI 名称。
- [x] 当前 1.2.1 提交按产品真实界面保留运行时识别名称与图标，并在审核备注中明确其仅用于识别用户选择的兼容主机端 CLI，不代表第三方背书。
- [x] 当前版本同时开放设备端与 Codex 转写；审核备注与隐私说明按真实数据流描述，不再沿用“仅设备端转写”的旧说明。

## 实现

审核备注必须明确：

1. iOS App 不下载或执行代码，命令只在用户配置的主机运行。
2. App 与电脑端免费开源，局域网、Tailscale 和自建 Tailcat 继续免费。可选订阅仅购买 Mimi 托管连接，不提供第三方账号、模型订阅、API Key、云端执行或项目托管。Mimi 运营订阅与设备授权服务及加密中继，无法读取代码、对话和文件内容。
3. 审核环境仅访问一次性样例仓库，网关限制目录并使用允许列表协议，不提供通用远程 Shell。
4. iOS 26 及以上默认使用设备端实时转写，并保留用户已保存的选择。用户仍可选择 Codex 转写，旧系统也使用此模式：录音会发送到用户配置的主机，再使用用户自己的主机端登录态请求转写。开发者不接收两种模式下的录音。
5. 拒绝相机、麦克风或语音权限后，仍可通过手动连接和键盘输入完成核心流程。
6. 无需 Mimi 账号。同一 Apple ID 恢复购买只恢复权益，不同步连接地址、私钥或 `agentd` Token；新手机或平板需重新接入每台电脑。

## 风险与优化

- Apple 上一轮已明确要求中国大陆版本处理 ChatGPT/OpenAI 关联；本轮即使采用中性元数据，仍可能因审核口径要求关闭相关兼容运行时。若再次收到同类拒绝，应先在 Resolution Center 解释“用户自有主机、无模型服务、托管中继只转发端到端加密数据”的边界，并附本构建变更点；不要连续无改动重提。
- Codex 语音转写会把录音交给模型提供方处理，是中国大陆审核的明确风险项；正式提交前必须确认审核策略，不能继续沿用“仅设备端”的旧说明。
- ICP/App 备案属于监管合规，不是文案技巧可以替代的步骤。若账号页面要求备案而当前没有号码，应先完成备案，再打开中国大陆销售范围。
- 正式提交前应使用 Apple 当前明确支持正式 App Store 上传的稳定版 Xcode 归档，避免用测试版工具链制造新的非业务阻塞。
