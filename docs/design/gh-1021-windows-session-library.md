# Windows 只读会话首页

Refs #1021 #974 #975 #977 #978 #991。

## 用户结果

完成首次设置后，进入现有 WinUI 窗口的“会话”页。沿用用户确认的 Fluent/Mica 方向：右侧内容列居中，宽度最多 1120 DIP；其他设置页最多 906 DIP。窗口缩小时项目筛选换行，列表独立滚动。

每行展示标题、渠道、项目和更新时间，右侧用图标与文字表达真实状态。按今天、昨天、最近 7 天、更早分组；缺失状态或时间明确显示未知。可按渠道、授权项目筛选，搜索仅限已加载记录。列表不提供点击打开、聊天、恢复、接管或审批操作。

## 数据与授权

- 只访问 `127.0.0.1` 上已有服务的端口；禁用代理和 HTTP 重定向。本机配对请求带 `X-Mimi-Local-Pairing: 1`，不带 Origin。凭据仅存在内存中，401 后清除，下次刷新重新获取。
- 从 `/api/app-server/config` 读取启用渠道，从 `/api/projects` 读取授权项目。项目选择向服务传递 cwd，客户端不扩大授权边界。
- Codex/Claude 使用已有 WebSocket 网关，只发送 initialize、initialized 和 thread/list；连接只带 runtime，不带具名 session。目录连接不会替换手机连接。
- DeepSeek 使用 `/api/harness/rpc` 的原生 session/list，参数为 `_request: {}`，解析原生 items/projections，不伪装成 Codex 协议。
- 身份由渠道和会话 ID 组成。过滤结构性子代理，保留正常 fork；不从标题猜测子代理。

## 分页与生命周期

Codex/Claude 首轮各读取最多 4 页，每页 50 条。加载更多将预算增加 4 页，使用新连接从头重放；不跨连接复用 opaque cursor。Harness 返回完整快照，不制造分页。

部分目录或单渠道失败时保留已有记录并提示可能过期；只有某渠道完整成功快照才可删除其旧记录。项目切换取消旧请求并清空旧范围，generation 防止迟到响应覆盖新范围。重复刷新合并为同一请求。

页面可见且窗口在前台时每 15 秒刷新，恢复前台和手动操作也会刷新；离开页面、隐藏或停用窗口时取消目录请求。连接页每 3 秒更新运行态，不覆盖尚未提交的中转输入。

## 验收边界

单元测试使用协议夹具和可控目录源验证授权请求、分页、失败、取消与竞态。`--debug-seed-ui` 使用虚构记录，可额外带 `--debug-dark` 或 `--debug-light` 检查主题，不修改系统主题或真实配置。

预览和单元测试不能代替真实手机并行连接、多屏 DPI、Narrator、Windows 10、签名更新以及安装器升级/回滚验收。正式安装与签名继续由 #979/#980 处理。
